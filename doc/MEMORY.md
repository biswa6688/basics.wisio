# Project Memory

Context and decisions that aren't obvious from the code alone. This is a project knowledge base, not a code reference — keep entries short and update them as decisions change.

## Product decisions

- **Name & tagline**: "Wisio" (from "wisdom"). Current tagline (as of 2026-08-30): **"Learn the Basics. Build Your Wisdom."** — this is the user's explicitly stated preferred choice from a list of options, applied throughout the app (nav, footer, hero badge, document titles) and docs. Superseded an earlier tagline, "Wisdom, Byte by Byte" (a bits/bytes wordplay tying the brand meaning to the subject matter), which shipped first and was corrected once the preference was made explicit — if the tagline changes again, update it everywhere in one pass rather than partially, since it appears in ~7 places across code and docs.
- **Primary color**: green (`#16a34a` / Tailwind-style 500 shade), chosen per explicit requirement. Full scale defined in `src/index.css` as `--color-primary-50..950`.
- **Content scope (v1)**: "Core basics" — Number Systems, How a Computer Works, Input & Output Devices, Operating Systems, Networking Basics, Internet Basics. A programming-intro track (variables/loops/data structures) was explicitly deferred to v3 in [BACKLOG.md](./BACKLOG.md), not dropped.
- **Illustration style**: 100% custom inline SVG (+ Framer Motion for motion), not stock images or icon-font illustrations. Reason: illustrations must always match the current theme's colors exactly, which is only reliably achievable when the SVG is theme-aware in code rather than a pre-rendered image asset.
- **Real reference photos, narrowly scoped and license-verified (2026-08-30)**: per explicit user request for real contextual photos across all 8 topics, one photo was added per lesson via `TopicPhoto` — sourced *only* from Wikimedia Commons (2 public domain: abacus, ENIAC; 6 CC-BY-SA/GPL with in-page attribution captions, which is the actual compliance mechanism, not decoration). The user's first instinct was "search the internet broadly" for images; that was explicitly declined — general web search results are overwhelmingly copyrighted with no reuse rights, and republishing them would be a real infringement risk, not a style tradeoff. Two Unsplash search results were caught and rejected mid-process because they turned out to be paid "Unsplash+ License" content despite appearing in free-tier search results — Unsplash mixes the two tiers in search with no reliable way to tell them apart except opening each photo's own page, which is why the final sourcing rule is Wikimedia-only. Full source table and the process for adding another photo: [PHOTO_CREDITS.md](./PHOTO_CREDITS.md); the exception to the no-raster rule is documented in [ILLUSTRATION_GUIDELINES.md](./ILLUSTRATION_GUIDELINES.md) section 3. Originals from Commons ran up to 11.7MB and were resized to 900–1200px JPEGs (15KB–270KB) with `ffmpeg` before committing.
- **`@antv/infographic`: rejected as a runtime dependency, adopted as an authoring-time tool (2026-08-30)**. First piloted as a live in-browser dependency (`new Infographic({container}).render(dslString)` imported directly into the app) — rejected: bundle size roughly tripled (gzipped JS ~132KB → ~405KB for one diagram), imperative DOM-mount API isn't idiomatic React, and it has no automatic dark/light reactivity (every theme change would need a manual re-render call, unlike the CSS-variable approach which repaints for free). The package was added and removed within the same session; net zero dependency diff.
  Re-evaluated per explicit user direction as an **authoring-time tool instead**: generate a diagram via the `infographic-creator` skill (its `SKILL.md` and DSL syntax, using `@antv/infographic` only as a design-time generator), export the real static SVG (`infographic.toDataURL({ type: 'svg' })`, confirmed working via Playwright automation), then hand-adapt it into a plain inlined component — same delivery mechanism as every hand-coded illustration, zero runtime dependency. Validated end-to-end on a CPU-cycle test render: clean output once given a short title and generous container height, transparent background (no dark-mode clash), colors already matched our palette (set via `theme.palette` in the DSL). But adaptation is real, non-trivial work confirmed against that actual export, not a formality — see the checklist in [ILLUSTRATION_GUIDELINES.md](./ILLUSTRATION_GUIDELINES.md): the export embedded an 85KB base64 font (87% of a 97KB file, needs stripping to `Inter`), and neutral text colors are static hex needing remapping to `var(--color-*)` tokens for dark-mode contrast. This is now the app's stated authoring policy (generate-then-adapt primary, hand-code failover), and it has been applied for real once: `CpuCycle` (How a Computer Works) was regenerated this way and now ships in the app. One more real bug surfaced during that swap, now folded into the checklist: **swapping `font-family` post-export can break layout** — `foreignObject` text boxes are pre-sized to fit the *original* font's measured character widths, so switching to `Inter` afterward can make text wider than its box, wrap, and overflow into whatever sits below (happened to the CPU Cycle title, fixed by widening that box and forcing `white-space: nowrap`). Safer fix for next time: pass the desired font via the DSL's `theme.base.text.font-family` at generation time instead of swapping it after the fact. The other 5 existing lesson diagrams stay hand-coded — none were judged a good fit (see [ILLUSTRATION_GUIDELINES.md](./ILLUSTRATION_GUIDELINES.md) for which fits and why).
  Two related Claude Code skills, both installed globally (`~/.claude/skills/`), do different things: `infographic-creator` is the one to use (generates an infographic); `infographic-structure-creator` is for contributing new structure *types* to the antv/infographic library's own source, not for generating an infographic instance — don't invoke it for diagram authoring.
- **Brand icon**: `public/wisio.svg` was copied from an existing brand asset (`owlia.svg`, an owl mascot) per explicit instruction, kept as-is rather than recolored to green — it's the fixed logo, not a themed illustration.
- **Visual redesign (2026-08-30)**: the initial v1 build (emoji icons, solid pastel-fill illustration blocks, pill-shaped nav/buttons, `rounded-2xl`/`rounded-full` everywhere, letter-in-colored-circle topic badges) read as a children's-education app, not a professional product. User explicitly called it "childish" and asked for a complete redesign toward "professional, educational, funplay like" (Duolingo/Brilliant register — polished with personality, not literal emoji/candy). Fixed by: replacing all emoji UI icons with `lucide-react` line icons (`src/data/topicIcons.tsx` centralizes topic→icon mapping), switching illustrations from solid-saturated fill blocks to outlined/tinted diagram style (`color-mix` accents), tightening border-radius from 2xl/full to lg/xl, replacing the pill-shaped active-nav-item and glowing CTA button with an underline nav indicator and a flat `rounded-lg` button, and loading real Inter typography instead of relying on the browser's fallback sans (which rendered heading weight as bubbly). The owl mascot logo was explicitly kept unchanged by user decision even though it's the most "playful" single element — see [CLAUDE.md](../CLAUDE.md) rule 7. This is now a locked design direction — see "Visual language" in [ARCHITECTURE.md](./ARCHITECTURE.md); don't reintroduce emoji-as-icon or solid pastel fills.

## Process decisions

- **Git remote**: `https://github.com/biswa6688/basics.wisio.git`. Repo was empty at project start (verified via `git ls-remote` returning no refs) — first push is a plain push, not a force-push.
- **Feature-at-a-time workflow**: explicit user requirement — commit + push prior valid work before starting each new feature, and update docs (FEATURES/TASKS/CHANGELOG/BACKLOG/ARCHITECTURE as relevant) in the same commit as the feature. Encoded in [CLAUDE.md](../CLAUDE.md) / [AGENTS.md](../AGENTS.md) so it persists across sessions.
- **Topic content is additive, not routed statically per-file**: `TopicPage` resolves content via a `slug -> component` registry (`src/pages/topics/registry.tsx`) so all topics exist in navigation from the first commit, with unbuilt lessons showing a "coming soon" state, rather than 404s or missing nav items appearing feature-by-feature.
- **Scope extended beyond v1 (2026-08-30)**: two more topics were added on top of the original 6-topic v1 set, sourced from the external "Computer Fundamentals" reference doc (see the Content merge entry above): **History of Computers** (early calculating machines through the five computer generations) and **Types of Computers** (analog/digital/hybrid classification, plus the supercomputer→mainframe→mini→micro size/power scale, with real-world applications folded in as a closing section rather than a ninth topic). The app is now 8 topics total. Per explicit user decision, the doc's remaining content (a full standalone Applications topic) was deliberately left out — see the content-merge scoping conversation for why.
